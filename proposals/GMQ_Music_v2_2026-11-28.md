## 2. What changed

- **Layers.** Old: 2 or 3 bare tones. New: a soft pad of chords, a melody, a low note, and small sounds of the place.
- **An echo made in code** (a reverb), one shared by every voice. It gives the "big room" feeling.
- **Chords that move.** 8 bars, not 4. A note that stays in the next chord is held, not played again: smoother, and fewer voices.
- **Longer before it repeats.** One time round is 26 to 30 seconds (old: 8 to 16).
- **Never the same twice in a row.** Each time round, each melody bar may play as written, change a few notes to other notes of the same chord, play one high note, or rest. Every third time round the melody rests ("a breath"). The first time round always plays the tune as written, so it can be learnt.
- **The place:**
  - The station: a low air rumble, and soft computer blips.
  - Voltara: a soft pulse whose filter opens bar by bar, like a charge building; small sparks; now and then a slow rising "charge" tone.
- **While a task box is open:** about 30% loudness (the same as today).
- **Still the same:** off until "Music" is tapped; starts only after a tap; pauses when the page is hidden; no sound files; nothing copied. I have not seen the summoning demo yet, so nothing is from it.

| Station, old | -25.0 dB | -32.3 dB | 6 |

| Station B | -25.6 dB | -37.1 dB | 12 |
| Voltara, old | -25.8 dB | -33.3 dB | 4 |
| Voltara A | -25.1 dB | -36.6 dB | 10 |
| Voltara B | -25.1 dB | -37.0 dB | 11 |
| The game's beep (a right answer) | -24.6 dB | | |

- **Quieter:** on average about 4 dB quieter than today. The loudest moments are no louder than one beep.
- **Voices:** never more than 14 at once (the limit). Tested on 2,000 random seeds per tune, 20 times round each: the most was 13. Chords, low notes and melody are never dropped; only extra blips or bells, when it is busy.
- **Cost:** making one minute took Chromium 1.5 to 4 seconds here, against about 1 second for the old tunes: about 3 times the work. Most of it is the echo. It is still small (a few % of one processor), but **it is not measured on an iPad.** If the class's oldest iPads stutter, the echo can be turned off (one line), which brings it close to the old cost.
- A cheaper echo (short repeats that feed back) was tried and dropped: it came out different each time it played, a sign it may misbehave in Safari.

## 4. Wiring it in (for the main thread, after Marc picks)

In `prototypes/kis_station_sketch.html`, the block `MUSIC.   [Source: Marc, 2026-11-22` …:

- **Remove:** `const TUNES = {…}`, `MUS`'s scheduling parts, `musParse`, `musNote`, `musTick`, `musStart`, `musStop`, `musWake`.
- **Keep:** `musPick()` (it already returns the place ids), the Music button, `getKeep('gmq-music')`, and the `visibilitychange` line (it suspends `AC`; the piece works with that).
- **Paste:** everything between `/* GMQ MUSIC: start` and `/* GMQ MUSIC: end */` from `docs/music/index.html`.
- **Then:**
  ```js
  GMQMusic.setup({ ctx: function () { AC = AC || new (window.AudioContext || window.webkitAudioContext)(); return AC; },
    pick: musPick,
    busy: function () { var t = false; try { t = speechSynthesis.speaking; } catch (e) {} return !!((typeof widget !== 'undefined' && widget) || READ.open || t); } });
  GMQMusic.setStyle('A');      // or 'B': Marc's pick
  if (getKeep('gmq-music') === 'on') GMQMusic.setOn(true);
  ['pointerdown', 'touchend', 'click', 'keydown'].forEach(function (ev) { document.addEventListener(ev, GMQMusic.wake, true); });
  ```
  The Music button calls `GMQMusic.setOn(on)` where it now sets `MUS.on` and calls `musStart`/`musStop`.
- **Until every place has a new tune,** a place without one is silent. So wire it in only when all ten are done (after Marc's pick), or keep the old player for the rest.
- `checks/music_test.js` reads `TUNES`, `musParse` and `MUS`: it must change with the wiring. `checks/music_v2_test.js` checks the piece itself.

## 6. How it was checked

- `checks/music_v2_test.js` (passes): the tunes as data (in key, in range, 8 bars, not an old melody); 2,000 seeds × 20 times round per tune and style (no two times round alike in a row, every note in key, melody in range, never over 14 voices, no core note dropped); a recording with a task open from 20 to 40 seconds (27% of the average, then back); a change of place (13 voices at most); silence 2 seconds after stop; live in Chromium (off at first, on, follows the place, busy down and back, a place with no tune is silent, off stops it); the page at iPad sideways, iPad upright and a phone (no sideways scrolling, buttons at least 44 px, tapping plays).
- `checks/music_v2_render.js` makes the recordings and `measures.json`. Needs Playwright and ffmpeg.
- **Not checked:** how it sounds; Safari/WebKit on an iPad (all checks ran in Chromium). The game file was not touched, so its tests were not run again.
