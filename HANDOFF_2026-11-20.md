## 2. How a change is made

1. **Edit the game file.** Each newer place sits between marks: `FINDS-BEGIN` to `FINDS-END` (the kit for finds: data in `FINDS`, locks in `FLOCK`, deep problems in `FPROB`, the time portal case in `FCASE` with `fClue` and `fBoard`, drawings in `FDRAW`, the check `fCheck`, one adapter for each planet in `FW`; only Chronosia is wired; guide: `proposals/GMQ_Finds_Kit_v1_2026-11-20.md`), `XYLO-BEGIN` to `XYLO-END` (Xylophora, state `S.xy` through `XY()`), `STAR-BEGIN` to `STAR-END` (Stardust, state `S.sd` through `SD()`). Bump the label in `#t_ver`. Avoid `?.` and `??`.
2. **Check it parses:** `node checks/parse_check.js`
3. **Run the test for the place you touched.** Tests are in `checks/`. `checks/RUN_ALL.md` says what each one is.
4. **The full run of all 30 play tests is PAUSED by Marc (2026-11-20), to save tokens.** Do not run it after every change. Run the parse check and the tests for what you touched. Run everything only when Marc asks, or when a change reaches into shared code (the reading card, the desk, the word rows, saving). Tell him which you did.
   - **What this costs:** a change in one place can break another, and nobody will see it until a child does. Say so when it matters.
   - **If you do run everything:** it takes about 35 minutes. Start it in the background and **do not poll it**. The session is woken when it ends. Polling every few minutes is what made the last thread expensive. Do not edit the game or any test while it runs.
   ```
   for c in checks/*_check.py; do echo "$c: $(python3 $c | tail -1)"; done
   for t in checks/*_test.js checks/picture_audit.js; do echo "$t: $(node $t 2>&1 | tail -1)"; done
   ```
5. **The class update check, before the copy:** `node checks/class_update_test.js docs/index.html prototypes/kis_station_sketch.html`. It opens games saved in the class copy inside the new copy.
6. **Copy to both links** [Marc, 23 November: every push goes to the class too]: `cp prototypes/kis_station_sketch.html docs/next/index.html && cp prototypes/kis_station_sketch.html docs/index.html`. Commit. Push.
7. **Check both links** show the new version: `curl -s <link> | grep -o 'id="t_ver">[^<]*'`. Pages takes a minute or two.
8. **Publish the artifact.**

**Keep long steps apart.** Test, then copy and commit, then push. The worker restarted once in the middle of one long command.

## 3. Marc's rules, learned the hard way

`CLAUDE.md` holds the standing rules. These are the ones he added while the game was being built. Each was broken once.

**About the game**

1. **A big quest is an open problem.** A purpose, bare facts, no steps. Try and fail. Nudges only when asked.
2. **Dead ends stay. Struggle is the point.** Fix what is broken (a question with two readings, a screen that jumps). Do not smooth what is hard.
3. **See the idea before you do it.** Show a finished example before asking for one. The example must not be about the same quantity as the question that follows.
4. **Your decision must matter.** What a child does must change something afterwards. A place can be left worse off. Kept on Voltara only, so far.
5. **A child must arrive and know where they are, what happened there, and what they are doing and why.** That is what Marc means by "story".
6. **Quite a few secrets in each place.** A thread a child pulls must lead somewhere.
7. **Short readings.** Commands are three or four words. Speech comes a sentence or two at a time.
8. **The picture stays still.** Nothing covers it. The page never scrolls on an iPad.
9. **The game must not decide a child has noticed something.** A state that changes what characters say may only be set by something the child did on purpose.

**Added 23 November:**
- **No maths as a password.** The maths must be what someone in the story really needs worked out, and the answer changes the world because of what it means. [Source: Marc, 23 November: "Why would that open a wall in the cave? ... You're not doing a cohesive story."] Many of Chronosia's finds break this; a story thread is reworking them.

**Added 21 November** (each was broken once):
- **Whatever the child is working on fills the picture.** The desk holds words, boxes and buttons. Since version 63, `toy()` moves any picture in a task (`.art`, `.picrow > .pic`, `svg.picsvg`, `[data-big]`) into `#stageview` over the picture, unless it holds a button or a box. A tool drawn on the canvas uses `olPic()` the same way.
- **Build for learning and the child's experience first, not for speed.** If you take a shortcut, say so.
- **The maths serves a task the child is told first.** The task serves the story.
- **Children know the story is not real.** Do not soften a story for fear of worrying them. [Marc, 2026-11-21: "Elementary students know this isn't real."]
- **Never show the adding for the child.** No running totals. The child does the sum and presses Check. [Marc, 2026-11-21]
- **Marc's 2023 pages are the floor, not a template.** Improve on them. Keep a 2023 idea only where it is still the best one. [Marc, 2026-11-21: "My 2023 is the floor. It can be improved."]

**About working with Marc**

10. **Do not make his decisions.** Options with what each costs, marked Proposal.
11. **Do not react too fast.** After a class report, ask how many got through before changing anything.
12. **When he sends a photo,** list everything in it that could be the trouble before answering.
13. **When he is stuck at his board, answer his screen first.** Read his numbers from the photo and tell him what to tap. Then find the fault.
14. **He writes by voice.** Words come out wrong ("chopped", "45 seconds"). Say how you read them.
15. **Write every message of his at the end of `INFO_FROM_MARC.md`,** with the date. Do not read that whole file. Search it.
16. **Plain English, short sentences, lists.** No student's details in this repository. It is public.

**About tokens**

- **Marc pays for every turn.** Keep replies short. Do not re-read big files. Do not poll a background job. Send a helper agent only when the reading is large.

**About tests**

17. **Test the worst case on purpose,** not a random cadet. The longest names, the smallest iPad.
18. **Never wait a fixed time for a walk.** Wait until the cadet has arrived.
19. **Check each word against the picture.** If the words say "under", look.
